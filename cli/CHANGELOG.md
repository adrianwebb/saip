# Changelog — @saip/cli

## [Unreleased]
### Added
- `profiles` returns data (`profileReport`) and a block builder (`profileBlocks`); the command renders through `ctx.ui`, so its human, log and machine outputs come from one content path — `--json` yields one record per block, each carrying `kind` (#156)
- `UiService`/`uiOr` gained `render(block)`, so a command can obtain a rendered string for a non-stdout sink (`awake`'s refusal) without rebuilding presentation by hand (#156)
- `tests/profiles-seam.test.ts` (14 cases: data-not-prose, block shape, plain/ink content parity, `--json` kind on every record, and a source-level guard that `console.log(` in `cli/src/commands` stays at zero); `tests/awake-profile-gate.test.ts` (3 cases covering `awake`'s and `status`'s deficit branches, with a `docker` tripwire); two alignment cases in `tests/ui-components.test.ts` (#156)
- `scripts/check-artifact-exit.ts` drives the COMPILED binary through a real pty and fails if a prompted command reports and then never exits; run by `binaries.yml` on every PR and on each native architecture (Windows excluded, not skipped — `node-pty` needs a different spawn path there) (#172)
- `ui/prompt.ts` gains `releaseTty()` (destroy + close the `/dev/tty` descriptor) and `promptingHappened()`; `UiService` exposes `releaseTerminal()`/`terminalHeld`; `runCli` releases in its `finally`, and `bin.ts` ends the process for any run that prompted, after draining buffered writes (#172)
- `tests/tty-release.test.ts` pins the three separate releases that #172 conflated — un-ref between questions (so #99's typed-ahead bytes survive), destroy at command end, and the entry point ending the process — including the ablation table as the record of what does NOT release Bun
- `config init` takes the `SecretAccess` gateway its command already owns and unlocks, lists and stores through it (`runInit` gained an `access` option, defaulting to a gateway over the same store so an embedder cannot ask twice either); `scripts/acceptance-110.ts` no longer answers a second passphrase prompt, so the row fails instead of absorbing the defect (#169)
- `tests/init-one-unlock.test.ts` drives the assembled command in a real pty and asserts exactly one `SAIP secret store passphrase:` across two secret writes, then reads the store back in a **second** process to prove the values landed rather than trusting the wizard's own report (#169)
- `probeHost()` returns a host's `HostStatus` to the caller and `saip status` renders mode, uptime, bucket and adapter count from it; `HostStatus.uptime` is read from docker's `{{.Status}}` field (#114)
- `materialiseKey`, `publicPath` and `writePublicKeypair` require the key directory; `storeKeyDir()` derives it from the store in hand; `sshKeyDir(env)` reads `env.HOME` before falling back to `homedir()` (#159)
- `tests/ssh-key-location.test.ts` pins the rule at command, library and assembled-artifact level, including a check that the real `~/.saip/keys` is unchanged by a full run (#159)
- pty harness (`tests/support/pty.ts`), screen model (`tests/support/screen.ts`) and a protocol-faithful fake tty (`tests/support/fake-tty.ts`), each with self-tests that prove they can fail — known exit code 7, a known hang, signal death reported as a signal and not as `code 0`, verbatim capture above the 64 KB pipe-buffer size, and isolation that refuses a path resolving inside the real `$HOME` (#154)
- `tests/ink-gate.test.ts` runs #154's gate rows against two candidate Ink engines; `tests/spikes/` holds the engines and the probe driver that produced the spike's evidence (#154)
- fixed in the harness itself: a child that exited before `finish()` was called was reported as **hung**, which briefly produced a false claim that the shipped CLI's `config set` never returned; the case is now pinned by a test that fails when the fix is reverted (#154)
- CLI skeleton with awake, sleep, down, status commands (#1)
### Fixed
- `tests/docs-flag-parity.test.ts` parses every flag row out of `cli-reference.mdx` and asserts the built program accepts it (#162): help output per command screens the pairs (9 spawns, not 30 — a per-pair version overran the test timeout), and anything the screen doubts is confirmed by passing the flag to the parser, so the failure names the doc line and quotes the parser. `AGENTS.md` now states that a documented flag or transcript is an interface contract
- `tests/support/screen.ts` gained the two margins it was missing (#176): it now **scrolls** at the bottom row and reverse-indexes at the top, and **wraps** at the right column on the next glyph instead of overwriting the last cell; `ESC[<n>A/B/G/H/f`, save/restore and `ESC[M` remain correct after a scroll. Six cases in `tests/screen.test.ts`, each proven red against the old model by reverting it
- `scripts/acceptance-110.ts` row 2 asserts content against the verbatim stream and placement against the screen model instead of asking the model a question it cannot answer — the false failure that was holding up the release gate (#176)
- **a prompted command no longer leaves the terminal frozen in the compiled binary** (#172). `config init` printed its full report and never exited; measured, Bun will not drain its loop once a `/dev/tty` reader has delivered data — `destroy()`, `closeSync()`, `pause()` and never-`ref()` all fail to release it while Node exits from each. The entry point now ends a run that prompted, after flushing so piped output cannot be truncated. Survived #145/#151 because every artifact check to date ran the binary only non-interactively
- `saip config init` asks for the store passphrase **once**, not twice: the wizard's writes went past the gateway to `store.set()`, and a store created by that write had no cached key for the read that followed — so the second prompt appeared and consumed the answer to the next question, leaving `SAIP_R2_SECRET_ACCESS_KEY` reported as stored and then listed as `still to fill` (#169)
`config init --non-interactive` reports `written now: 0` and `to fill:` instead of calling set values `missing` and claiming `stored N value(s)`; `awake`/`sleep`/`down` resolve the host before printing their action line (#150)
- `--json` produces one parseable record for parse-level outcomes too (missing argument, unknown option, unknown command, `--help`, `--version`), so stdout is never empty under `--json`; the guard is applied per subcommand and exit codes are restored after `exitOverride` (#147)
- `config set` verifies against the encrypted store rather than the env-first resolution chain, so a shadowed name no longer produces a false `did not persist` failure; the shadow is reported as a note, and only a genuine store mismatch can fail the command (#146)
- unknown-host errors carry the role and flag that fixes them (`unknown deploy source host … — set --source <name>`), and the known-host list truncates at eight with `+N more` (#117)
- `saip status` placeholders (`TODO (awake / asleep / down)`, `TODO`, `TODO (R2 bucket name)`, a zero adapter count rendered as `TODO`) are replaced by real values or explained absences; an unreachable host reports `unknown` with its reason rather than `down`; `--adapter-resolution` had been documented while the flag never existed and is removed from the CLI reference (#114)
