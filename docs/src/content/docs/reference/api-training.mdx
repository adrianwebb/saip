title: Training Gateway API
description: HTTP endpoints for data ingestion and learning management, organized as Data API and Learning API

The training gateway listens on the port configured in `training.port` (default `8001`). All endpoints accept and return JSON.

Base URL: `http://<host>:<training.port>`

The API is organized into two surfaces:

- **Data API** (`/v1/data/*`) — document upload, processing, storage, and retrieval
- **Learning API** (`/v1/learning/*`) — training strategy registration, job management, feedback, and optimization

## Architecture Overview

The training gateway uses **two plugin registries** connected by a clean interface contract:

```
Data Type Plugins              Training Strategy Plugins
─────────────────              ─────────────────────────
markdown-processor        →    knowledge-embedding
code-processor            →    corrective-sft
pdf-processor             →    weighted-kto
jsonl-processor           →    (future strategies...)
(future types...)         →
```

Each **data type plugin** implements a standard interface: accept a raw document, return processed output in the canonical intermediate format. Each **training strategy plugin** implements another standard interface: accept processed output of declared types, produce an Axolotl dataset in the strategy's required format. Neither knows about the other's internals — they communicate through the interface contract only.

This means:
- Adding a new document type (LaTeX, HTML, audio transcripts) = one new data type plugin, zero changes to strategies
- Adding a new training method (GRPO replay, DPO) = one new strategy plugin, zero changes to data processors
- A strategy declares which data types it accepts; the registry handles routing
- Multiple strategies can consume the same processed output simultaneously

Both plugin types are Cordis plugins that register themselves at startup. The training gateway orchestrates the flow:

```
Upload → Validation → Dedup → Data Type Plugin → Intermediate Format
                                                        ↓
                                        Training Strategy Plugins (matching types)
                                        ├── Knowledge Embedding → completion datasets
                                        ├── Corrective SFT → feedback-weighted messages
                                        ├── Weighted KTO → scalar reward records
                                        └── ...extensible
```

Neither plugin type splits or chunks data — they transform formats based on rules.

# Data API

## POST /v1/data/documents

Submit a document for processing. The document type router inspects the content and routes it to the appropriate document processor plugin.

### Request Headers

| Header         | Required | Description              |
|----------------|----------|--------------------------|
| `Content-Type` | Yes      | `application/json`       |

### Request Body

| Field         | Type                                | Required | Description                                |
|---------------|-------------------------------------|----------|--------------------------------------------|
| `source`      | `string`                            | Yes      | Origin URI or description.                 |
| `source_type` | `'document' \| 'repository' \| 'dataset'` | Yes | Source classification.              |
| `content`     | `string`                            | Yes      | Raw document content.                      |
| `license`     | `string`                            | No       | SPDX license identifier.                   |
| `tags`        | `string[]`                          | No       | Classification tags.                       |

### Response `201 Created`

```json
{
  "id": "doc-20250115-001",
  "source": "internal-wiki/onboarding.md",
  "source_type": "document",
  "hash": "sha256:a1b2c3...",
  "size_bytes": 4096,
  "processed_by": "markdown-processor",
  "created_at": "2025-01-15T10:30:00Z"
}
```

### Example

```bash
curl -X POST http://localhost:8001/v1/data/documents \
  -H "Content-Type: application/json" \
  -d '{
    "source": "internal-wiki/onboarding.md",
    "source_type": "document",
    "content": "# Onboarding Guide\n...",
    "tags": ["onboarding", "hr"]
  }'
```

## GET /v1/data/documents

List all ingested documents.

### Query Parameters

| Parameter | Type     | Description                              |
|-----------|----------|------------------------------------------|
| `tag`     | `string` | Filter by tag (repeatable).              |
| `limit`   | `number` | Maximum entries to return. Default `50`. |
| `offset`  | `number` | Pagination offset. Default `0`.          |

### Response `200 OK`

```json
{
  "entries": [
    {
      "id": "doc-20250115-001",
      "source": "internal-wiki/onboarding.md",
      "source_type": "document",
      "hash": "sha256:a1b2c3...",
      "size_bytes": 4096,
      "processed_by": "markdown-processor",
      "tags": ["onboarding", "hr"],
      "created_at": "2025-01-15T10:30:00Z"
    }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

## DELETE /v1/data/documents/:id

Remove a document and its processed outputs.

### Response `204 No Content`

# Learning API

## GET /v1/learning/strategies

List registered training strategy plugins.

### Response `200 OK`

```json
{
  "strategies": [
    {
      "name": "knowledge_embedding",
      "description": "Continued pretraining on completion-format datasets",
      "accepted_source_types": ["document", "repository", "dataset"],
      "configurable_params": ["epochs", "learning_rate", "sequence_len"]
    },
    {
      "name": "corrective_sft",
      "description": "Supervised fine-tuning with per-turn feedback weighting",
      "accepted_source_types": ["session", "feedback"],
      "configurable_params": ["epochs", "learning_rate", "turn_weighting"]
    },
    {
      "name": "weighted_kto",
      "description": "Preference learning with scalar reward magnitudes",
      "accepted_source_types": ["feedback"],
      "configurable_params": ["reward_range", "magnitude_weights"]
    }
  ]
}
```

## POST /v1/learning/jobs

Trigger a new training job using a registered training strategy.

### Request Body

| Field           | Type     | Required | Description                                          |
|-----------------|----------|----------|------------------------------------------------------|
| `strategy`      | `string` | Yes      | Name of a registered training strategy plugin.       |
| `adapter_id`    | `string` | No       | Target adapter ID. Defaults to user's training adapter. |
| `data_ids`      | `string[]` | No     | Document/feedback IDs to include as training input.  |
| `params`        | `object` | No       | Strategy-specific parameter overrides.               |

### Response `202 Accepted`

```json
{
  "job_id": "train-20250115-001",
  "strategy": "knowledge_embedding",
  "status": "queued",
  "created_at": "2025-01-15T12:00:00Z"
}
```

### Example

```bash
curl -X POST http://localhost:8001/v1/learning/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "strategy": "knowledge_embedding",
    "data_ids": ["doc-20250115-001"],
    "params": {
      "epochs": 3,
      "learning_rate": 2e-5
    }
  }'
```

## GET /v1/learning/jobs

List training jobs.

### Query Parameters

| Parameter  | Type     | Description                                          |
|------------|----------|------------------------------------------------------|

| `offset`   | `number` | Pagination offset. Default `0`.                      |

```json
  "offset": 0
```
```json
}
```

## POST /v1/learning/feedback

Submit a feedback record linked to a session. Used as reward signal for weighted KTO and corrective SFT training strategies.

### Request Body

| Field           | Type                      | Required | Description                                            |
|-----------------|---------------------------|----------|--------------------------------------------------------|
| `session_id`    | `string`                  | Yes      | Session this feedback refers to.                       |
| `message_id`    | `string`                  | No       | Specific message within the session.                   |
| `reward`        | `number`                  | Yes      | Scalar reward (must be within configured `reward_range`). |
| `confidence`    | `number`                  | No       | Confidence weight (0–1).                               |
| `dimensions`    | `Record<string, number>`  | No       | Multi-dimensional reward breakdown.                    |
| `feedback_text` | `string`                  | No       | Free-form human commentary.                            |

### Response `201 Created`

```json
{
  "id": "fb-20250115-001",
  "session_id": "sess-abc123",
  "reward": 2,
  "confidence": 0.9,
  "created_at": "2025-01-15T11:00:00Z"
}
```

### Example

```bash
curl -X POST http://localhost:8001/v1/learning/feedback \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "sess-abc123",
    "reward": 2,
    "confidence": 0.9,
    "feedback_text": "Accurate and well-structured response."
  }'
```

## GET /v1/learning/feedback

List feedback records.

### Query Parameters

| Parameter    | Type     | Description                                    |
|--------------|----------|------------------------------------------------|
| `session_id` | `string` | Filter by session ID.                          |
| `min_reward` | `number` | Minimum reward threshold.                      |
| `max_reward` | `number` | Maximum reward threshold.                      |
| `limit`      | `number` | Maximum records to return. Default `50`.       |
| `offset`     | `number` | Pagination offset. Default `0`.                |

## Error Responses

All endpoints return standard HTTP error codes with a JSON body:

```json
{
  "error": {
    "message": "Description of the error",
    "type": "invalid_request_error",
    "code": "document_not_found"
  }
}
```

| Status | Meaning                                                  |
|--------|----------------------------------------------------------|
| `400`  | Malformed request, invalid reward range, missing fields. |
| `404`  | Referenced session, document, or job not found.          |
| `409`  | Training job conflict (GPU busy, duplicate submission).  |
| `422`  | Reward outside configured `reward_range`.                |
| `500`  | Internal error (Axolotl failure, R2 write failure).      |
| `503`  | Training subsystem unavailable (GPU offline).            |
