The training gateway listens on the port configured in `training.port` (default `8001`). All endpoints accept and return JSON.

Base URL: `http://<host>:<training.port>`

The training gateway exposes a single API surface:

- **Learning API** (`/v1/learning/*`) — training strategy registration, job management, feedback, and optimization

Data ingestion is handled by the inference gateway (see [Inference API](/saip/reference/api-inference/)). Processed data flows between the two services via R2 object storage.

## Authentication

Job-mutating routes (`POST /v1/learning/jobs`) are protected by the same pluggable
[AuthProvider](/saip/reference/security-model/) as the inference gateway: send `Authorization: Bearer <token>`, and the authenticated caller's default training adapter is used unless the request names one explicitly. **Fail-closed** — without a valid bearer token (and with `security.dev_mode` false), requests receive `401`. Read-only routes such as `GET /v1/learning/strategies` may remain open depending on deployment policy.

## Architecture Overview

The SAIP platform separates concerns across two gateways with **R2 as the handoff boundary**:

```
┌─────────────────────────────┐          ┌─────────────────────────────┐
│    Inference Gateway        │          │     Training Gateway        │
│                             │          │                             │
│  Data API (/v1/data/*)      │          │  Learning API (/v1/learning)│
│  Document Processors        │          │  Training Strategy Plugins  │
│  ├─ markdown-processor      │          │  ├─ knowledge-embedding     │
│  ├─ code-processor          │          │  ├─ corrective-sft          │
│  ├─ pdf-processor (Marker)  │          │  ├─ weighted-kto            │
│  └─ jsonl-processor         │          │  └─ (future strategies...) │
│                             │          │                             │
│  Writes processed data ──────────► R2 ◄──── Reads processed data    │
│                             │          │                             │
│  Serves model inference     │          │  Runs Axolotl training jobs │
└─────────────────────────────┘          └─────────────────────────────┘
```

### Why This Separation

Document processing often requires model inference — OCR via Marker for PDFs, code analysis, structured extraction. Running these processors on the training GPU would compete with training workloads. By placing the Data API and document processors in the inference gateway:

- The **inference GPU** handles both model serving and document processing during awake mode
- The **training GPU** is 100% dedicated to Axolotl fine-tuning jobs
- R2 serves as a clean handoff boundary: inference writes processed data, training reads it

### Training Strategy Plugins

Each **training strategy plugin** declares which intermediate output formats it can consume from R2. When a learning job references a strategy, the registry loads matching processed data and produces Axolotl datasets in the required format.

Adding a new training method requires only one new strategy plugin — zero changes to data processors or the inference gateway. Multiple strategies can consume the same processed output simultaneously.

The training gateway orchestrates the flow:

```
R2 (processed data) ──→ Training Strategy Plugins
                         ├── knowledge-embedding → completion datasets
                         ├── corrective-sft      → feedback-weighted SFT datasets
                         ├── weighted-kto        → KTO datasets with magnitude weights
                         └── ...extensible
                                ↓
                          Axolotl Runner
                                ↓
                           QLoRA Adapter
                                ↓
                  Upload to R2 + update index
```

# Learning API

## GET /v1/learning/strategies

List registered training strategy plugins.

### Response `200 OK`

```json
{
  "strategies": [
    {
      "name": "knowledge_embedding",
      "description": "Continued pretraining on completion-format datasets",
      "accepted_source_types": ["document", "repository", "dataset"],
      "configurable_params": ["epochs", "learning_rate", "sequence_len"]
    },
    {
      "name": "corrective_sft",
      "description": "Supervised fine-tuning with per-turn feedback weighting",
      "accepted_source_types": ["session", "feedback"],
      "configurable_params": ["epochs", "learning_rate", "turn_weighting"]
    },
    {
      "name": "weighted_kto",
      "description": "Preference learning with scalar reward magnitudes",
      "accepted_source_types": ["feedback"],
      "configurable_params": ["reward_range", "magnitude_weights"]
    }
  ]
}
```

## POST /v1/learning/jobs

Trigger a new training job. Jobs target a **leaf adapter** in the registry; when `strategy` and data selection are omitted, they are inherited from the adapter's declared [training linkage](/saip/reference/adapter-definitions/#training-linkage-training).

### Request Body

| Field           | Type     | Required | Description                                          |
|-----------------|----------|----------|------------------------------------------------------|
| `adapter`       | `string` | No       | Target adapter name from the registry. Defaults to the caller's `users[].adapters.training`. Must be a leaf — composites return `422`. |
| `strategy`      | `string` | No       | Registered training strategy plugin. Defaults to the adapter's declared `training.strategy`. |
| `data_ids`      | `string[]` | No     | Explicit document/session/feedback IDs. Default: all untrained data within the adapter's declared `data_scopes`. |
| `params`        | `object` | No       | Strategy-specific parameter overrides (defaults merge from the adapter's `training.params`). |

:::note[Adapter → Strategy → Data Path]
The registry is what makes this chain explicit: `user → users[].adapters.training → adapter definition → training.strategy + training.data_scopes → matching strategy plugin → dataset`. A job that names only an adapter inherits everything else; explicit fields override per-job for experimentation.
:::

### Response `202 Accepted`

```json
{
  "job_id": "train-20250115-001",
  "adapter": "treeseed-project",
  "strategy": "corrective_sft",
  "inherited": { "data_scopes": ["sessions", "feedback"] },
  "status": "queued",
  "created_at": "2025-01-15T12:00:00Z"
}
```

### Errors

| Status | Condition |
|--------|-----------|
| `422` | `adapter` names a composite (`trainable: false`) or unknown strategy |
| `404` | Adapter not found in registry |

### Example

```bash
# Minimal: inherit strategy + data scopes from the adapter's registry entry
curl -X POST http://localhost:8001/v1/learning/jobs \
  -H "Content-Type: application/json" \
  -d '{ "adapter": "treeseed-project" }'

# Explicit: override strategy params for one experiment
curl -X POST http://localhost:8001/v1/learning/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "adapter": "coding",
    "strategy": "knowledge_embedding",
    "data_ids": ["doc-20250115-001"],
    "params": { "epochs": 3, "learning_rate": 2e-5 }
  }'
```

## GET /v1/learning/jobs

List training jobs.

### Query Parameters

| Parameter  | Type     | Description                                          |
|------------|----------|------------------------------------------------------|
| `status`   | `string` | Filter by status (`queued`, `running`, `completed`, `failed`). |
| `strategy` | `string` | Filter by training strategy name.                    |
| `limit`    | `number` | Maximum jobs to return. Default `20`.                |
| `offset`   | `number` | Pagination offset. Default `0`.                      |

### Response `200 OK`

```json
{
  "jobs": [
    {
      "job_id": "train-20250115-001",
      "strategy": "knowledge_embedding",
      "status": "running",
      "adapter_id": "general",
      "progress": 0.45,
      "created_at": "2025-01-15T12:00:00Z",
      "started_at": "2025-01-15T12:01:00Z"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```

## POST /v1/learning/feedback

Submit a feedback record linked to a session. Used as reward signal for weighted KTO and corrective SFT training strategies.

### Request Body

| Field           | Type                      | Required | Description                                            |
|-----------------|---------------------------|----------|--------------------------------------------------------|
| `session_id`    | `string`                  | Yes      | Session this feedback refers to.                       |
| `message_id`    | `string`                  | No       | Specific message within the session.                   |
| `reward`        | `number`                  | Yes      | Scalar reward (must be within configured `reward_range`). |
| `confidence`    | `number`                  | No       | Confidence weight (0–1).                               |
| `dimensions`    | `Record<string, number>`  | No       | Multi-dimensional reward breakdown.                    |
| `feedback_text` | `string`                  | No       | Free-form human commentary.                            |

### Response `201 Created`

```json
{
  "id": "fb-20250115-001",
  "session_id": "sess-abc123",
  "reward": 2,
  "confidence": 0.9,
  "created_at": "2025-01-15T11:00:00Z"
}
```

### Example

```bash
curl -X POST http://localhost:8001/v1/learning/feedback \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "sess-abc123",
    "reward": 2,
    "confidence": 0.9,
    "feedback_text": "Accurate and well-structured response."
  }'
```

## GET /v1/learning/feedback

List feedback records.

### Query Parameters

| Parameter    | Type     | Description                                    |
|--------------|----------|------------------------------------------------|
| `session_id` | `string` | Filter by session ID.                          |
| `min_reward` | `number` | Minimum reward threshold.                      |
| `max_reward` | `number` | Maximum reward threshold.                      |
| `limit`      | `number` | Maximum records to return. Default `50`.       |
| `offset`     | `number` | Pagination offset. Default `0`.                |

## Error Responses

All endpoints return standard HTTP error codes with a JSON body:

```json
{
  "error": {
    "message": "Description of the error",
    "type": "invalid_request_error",
    "code": "document_not_found"
  }
}
```

| Status | Meaning                                                  |
|--------|----------------------------------------------------------|
| `400`  | Malformed request, invalid reward range, missing fields. |
| `404`  | Referenced session or job not found.                     |
| `409`  | Training job conflict (GPU busy, duplicate submission).  |
| `422`  | Reward outside configured `reward_range`.                |
| `500`  | Internal error (Axolotl failure, R2 read/write failure). |
| `503`  | Training subsystem unavailable (GPU offline).            |
