---
title: Configuration Reference (saip.yaml)
description: Complete schema reference for the SAIP platform configuration file
---

The `saip.yaml` file at the repository root defines all platform configuration. Secrets are never stored in this file; they are loaded from `.env` or environment variables via `${ENV_VAR}` interpolation.

## platform

| Field     | Type     | Default | Description                          |
|-----------|----------|---------|--------------------------------------|
| `name`    | `string` | —       | Platform identifier.                 |
| `version` | `string` | —       | Semantic version of the deployment.  |

```yaml
platform:
  name: saip
  version: "0.1.0"
```

## model

Base-model settings. Each field is a **default that the active [service profile](/saip/reference/hardware-profiles/)
may override** — the profile owns the values that are hardware-dependent, because a single
constant cannot be correct across cards.

| Field            | Type     | Default | Description                                                        |
|------------------|----------|---------|--------------------------------------------------------------------|
| `base`           | `string` | —       | HuggingFace model ID. Reference checkpoint: `QuantTrio/Qwen3.5-4B-AWQ` (community AWQ build; no official Qwen AWQ exists for this model). |
| `revision`       | `string` | —       | Pin the checkpoint by commit hash. Recorded in the adapter manifest so an adapter names the base it was validated against. |
| `quantization`   | `string` | `awq`   | Quantization method: `awq`, `gptq`, `bitsandbytes`, or `none`. Must match a checkpoint that is *already* quantized in that format — vLLM cannot AWQ-quantize a BF16 checkpoint at load time. `bitsandbytes` is not a supported multi-LoRA serving path. |
| `max_model_len`  | `number` | profile | Maximum context length passed to vLLM. Ceiling is profile-dependent: 24,576 on `inference-8gb`, 65,536 on `full-loop-12gb`. |
| `dtype`          | `string` | `auto`  | Torch dtype (`float16`, `bfloat16`, `auto`). `bfloat16` needs compute capability ≥ 8.0. |
| `language_model_only` | `boolean` | `true` | Skip the vision encoder (~0.6 GiB saved). Required on the 8 GB tier; disables image/video inputs. |
| `kv_cache_dtype` | `string` | `auto`  | KV cache storage dtype. **Do not set `fp8*` or `int8_per_token_head` below compute capability 8.9** — validation rejects it, because the accepted-but-corrupting case produces garbage output with no error. |

```yaml
model:
  base: "QuantTrio/Qwen3.5-4B-AWQ"
  revision: "32c292e3a73afe1138518180b1b6d2868c980ee2"
  quantization: "awq"
  dtype: "auto"
  language_model_only: true
  kv_cache_dtype: "auto"
```

## profile / profiles

`profile` names the active service profile; `profiles` declares them. Profiles are the
hardware contract — see [Hardware Profiles](/saip/reference/hardware-profiles/) for the measured
ceilings and the capability matrix.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `profile` | `string` | auto-resolved | Which entry in `profiles` to run. Omit to probe the GPU and select the highest tier it satisfies. |
| `profiles.<name>` | `object` | — | A named profile. Requires `min_vram_gib` and `min_capability`; carries `vram_ceiling_gib` and the engine arguments for that tier. |

```yaml
# profile: inference-8gb        # unset = resolve from the probed GPU; set = pin a tier

profiles:
  inference-8gb:
    description: Serve only; 8 GB consumer card
    min_vram_gib: 8
    min_capability: 7.5
    vram_ceiling_gib: 7.0
    engine:
      max_model_len: 24576
      kv_cache_dtype: auto
      enforce_eager: true
      enable_lora: true
      max_loras: 4
      max_lora_rank: 16
  full-loop-12gb:
    description: Serve and fine-tune, time-shared via awake/sleep
    min_vram_gib: 12
    min_capability: 8.0
    vram_ceiling_gib: 11.0
    engine:
      max_model_len: 65536
      kv_cache_dtype: auto
      enforce_eager: false
      enable_lora: true
      max_loras: 4
      max_lora_rank: 16
    training:
      precision: bf16
      sequence_len: 2048
      gradient_checkpointing: true
      optimizer: adamw_bnb_8bit
```

`gpu_memory_utilization` is **not settable as a constant** — it is derived from the
profile ceiling divided by total VRAM and validated against measured free memory at
launch. `SAIP_GPU_MEMORY_UTILIZATION` may override it downward on a shared GPU.

:::note[Validation]
`profiles` is validated by `ProfileService` in `@saip/shared` at boot, identically for the
CLI, inference gateway, and training gateway. A profile whose card requirements are not
met fails startup with exit code 2 naming the deficit — it is never allowed to OOM later.
:::

## adapter

Global LoRA adapter defaults applied when a training job does not specify overrides.

| Field            | Type       | Default | Description                                                |
|------------------|------------|---------|------------------------------------------------------------|
| `default_rank`   | `number`   | —       | Default LoRA rank (`r`).                                   |
| `default_alpha`  | `number`   | —       | Default LoRA scaling factor (`alpha`).                     |
| `target_modules` | `string[]` | —       | Linear module names to apply LoRA adapters to.             |

```yaml
adapter:
  default_rank: 16
  default_alpha: 32
  target_modules:
    - q_proj
    - k_proj
    - v_proj
    - o_proj
    - gate_proj
    - up_proj
    - down_proj
```

## storage

### storage.r2

Cloudflare R2 object storage configuration. Credentials (`SAIP_R2_ACCESS_KEY_ID`, `SAIP_R2_SECRET_ACCESS_KEY`) are loaded from `.env`.

| Field      | Type     | Interpolation | Description                            |
|------------|----------|---------------|----------------------------------------|
| `bucket`   | `string` | ✅ `${…}`     | R2 bucket name.                        |
| `endpoint` | `string` | ✅ `${…}`     | R2 S3-compatible endpoint URL.         |

```yaml
storage:
  r2:
    bucket: "${SAIP_R2_BUCKET}"
    endpoint: "${SAIP_R2_ENDPOINT}"
```

### storage.huggingface

| Field       | Type     | Interpolation | Description                                                    |
|-------------|----------|---------------|----------------------------------------------------------------|
| `token_env` | `string` | ❌            | Name of the environment variable containing the HF API token.  |

```yaml
  huggingface:
    token_env: "SAIP_HF_TOKEN"
```

## adapters

Array of first-class adapter definitions — the **adapter registry**. Entries are independent of users and scoped (`global` / `domain` / `project` / `user`). Each entry is a leaf (declares `training:` linkage) or a composite (declares `composite:` weights). Full contract: [Adapter Definitions](/saip/reference/adapter-definitions/).

| Field | Type | Description |
|-------|------|-------------|
| `name` | `string` | Unique adapter name (required) |
| `scope` | enum | `global`, `domain`, `project`, `user` (required) |
| `project` / `user` | `string` | Owner annotation; `project` required when scope=`project` |
| `description` | `string` | Human-readable purpose |
| `trainable` | `boolean` | Default `true`; `false` for derived composites |
| `base` | `string` | Target base model; components must match at compile |
| `training.strategy` | `string` | Registered training strategy plugin (leaf, required) |
| `training.data_scopes` | `string[]` | Data types feeding training (leaf, required) |
| `training.params` | `object` | Strategy-specific job defaults |
| `composite.gain` | `number` | Overall λ on merged delta (default 1.0) |
| `composite.merge` | enum | `weighted_linear` (default), `ties`, `dare` |
| `composite.components[].adapter` | `string` | Component name (cycle-free) |
| `composite.components[].weight` | `number` | Per-component weight wᵢ |
| `composite.components[].version` | `string` | Optional pin (e.g. `@000012`); default `@latest` |

```yaml
adapters:
  - name: coding
    scope: global
    training:
      strategy: knowledge_embedding
      data_scopes: [documents]

  - name: northstar-architect
    scope: user
    trainable: false
    composite:
      gain: 1.25
      components:
        - { adapter: coding, weight: 0.7 }
        - { adapter: treeseed-project, weight: 1.0 }
```

## users

Array of user-to-adapter mappings. Each entry binds a user ID to specific adapters for inference and training. Names resolve through the adapter registry — `inference` may reference a composite.

| Field                | Type     | Description                                                     |
|----------------------|----------|-----------------------------------------------------------------|
| `id`                 | `string` | User identifier.                                                |
| `adapters.inference` | `string` | Adapter alias or ID used for inference (e.g. `northstar-architect@latest`). May be a composite. |
| `adapters.training`  | `string` | Leaf adapter that receives this user's training jobs.           |

```yaml
users:
  - id: "default"
    adapters:
      inference: "default-agent@latest"
      training: "general"
```

## inference

Inference gateway service configuration.

| Field               | Type      | Default | Description                                                          |
|---------------------|-----------|---------|----------------------------------------------------------------------|
| `port`              | `number`  | —       | HTTP port for the inference API.                                     |
| `gpu_node`          | `string`  | —       | GPU node identifier for scheduling.                                  |
| `max_loras`         | `number`  | —       | Maximum number of LoRA adapters loaded on GPU simultaneously.        |
| `max_cpu_loras`     | `number`  | —       | Maximum number of LoRA adapters cached on CPU for hot-swapping.      |
| `systemone.enabled` | `boolean` | —       | Enable SystemOne structured-output endpoints alongside chat completions. |

```yaml
inference:
  port: 8000
  gpu_node: "local"
  max_loras: 4
  max_cpu_loras: 32
  systemone:
    enabled: true
```

## training

Training gateway service configuration.

| Field    | Type     | Default | Description                              |
|----------|----------|---------|------------------------------------------|
| `port`   | `number` | —       | HTTP port for the training API.          |
| `gpu_node` | `string` | —     | GPU node identifier for scheduling.      |

### training.methods

Each method has an `enabled` boolean and method-specific parameters.

#### knowledge_embedding

| Field          | Type      | Description                                          |
|----------------|-----------|------------------------------------------------------|
| `enabled`      | `boolean` | Enable knowledge-embedding training method.          |
| `sequence_len` | `number`  | Maximum sequence length for embedding training data. |

#### corrective_sft

| Field          | Type      | Description                                          |
|----------------|-----------|------------------------------------------------------|
| `enabled`      | `boolean` | Enable corrective supervised fine-tuning method.     |
| `sequence_len` | `number`  | Maximum sequence length for SFT training data.       |

#### weighted_kto

| Field               | Type               | Description                                                           |
|---------------------|--------------------|-----------------------------------------------------------------------|
| `enabled`           | `boolean`          | Enable weighted Kahneman-Tversky Optimization method.                 |
| `reward_range`      | `[number, number]` | Min/max reward values (e.g. `[-3, 3]`).                               |
| `magnitude_weights` | `Record<int, float>` | Weight multiplier per absolute reward magnitude. Keys are integers. |

```yaml
training:
  port: 8001
  gpu_node: "local"
  methods:
    knowledge_embedding:
      enabled: true
      sequence_len: 4096
    corrective_sft:
      enabled: true
      sequence_len: 4096
    weighted_kto:
      enabled: true
      reward_range: [-3, 3]
      magnitude_weights:
        1: 0.5
        2: 1.0
        3: 1.5
```

## plugins

Array of Cordis plugin entries to load into both gateways. Each entry is a plugin specifier understood by the Cordis loader.

| Field | Type    | Description                                    |
|-------|---------|------------------------------------------------|
| —     | `any[]` | Plugin specifiers (strings, objects, or maps). |

```yaml

```

## Environment Variable Interpolation

Fields marked with ✅ in the tables above support `${ENV_VAR}` syntax. At load time, each `${VAR}` token is replaced with the value of the corresponding environment variable. Missing variables cause a startup error.

Supported fields:
- `storage.r2.bucket`
- `storage.r2.endpoint`

All other fields are literal values. Secret values (API keys, tokens) should be referenced by their env-var *name* (e.g. `token_env: "SAIP_HF_TOKEN"`) rather than interpolated directly.

## Inference Gateway → vLLM Engine

How the gateway reaches the engine is **deployment configuration, not platform
configuration**: it changes per host, per network namespace, and per container restart, so it
lives in environment variables rather than `saip.yaml`.

| Variable | Default | Description |
|----------|---------|-------------|
| `SAIP_VLLM_BASE_URL` | — | OpenAI-compatible base URL of the engine, including the `/v1` path segment (e.g. `http://vllm:8000/v1` in-network, `http://localhost:8081/v1` from the host). **Unset means no engine is attached**: the gateway boots, serves `/health` and `/v1/models`, and answers `/v1/chat/completions` with `503 backend_unavailable`. It never guesses a localhost port, because silently connecting to whatever happens to be listening is how a request gets served by the wrong model. |
| `SAIP_VLLM_API_KEY` | — | Optional bearer token, for engines fronted by a gateway. SAIP does not authenticate to vLLM itself. |
| `SAIP_VLLM_TIMEOUT_MS` | `180000` | Per-request ceiling. Prefill on an 8 GB card can run minutes; a short value surfaces as an opaque gateway error rather than a slow response. |
| `SAIP_VLLM_MAX_RETRIES` | `1` | Retries for connection failures only. A 4xx/5xx from the engine is a real answer and is **not** retried — resending a generation request risks duplicate work and duplicate recorded sessions. |

Adapters are addressed through the standard OpenAI `model` field rather than a SAIP-specific
parameter: vLLM exposes each loaded LoRA adapter as a model name, so the gateway resolves a
caller to `name@version` and passes it as `model`. Switching users therefore requires no
engine restart, and the engine stays a plain OpenAI server that SAIP can be swapped away
from.

Engine **arguments** — model, context length, KV dtype, VRAM ceiling — come from the active
[service profile](../hardware-profiles/), rendered per host into `inference/.engine-args.env`
by `inference/scripts/generate-engine-args.ts`. They are deliberately not read from these
variables, because `--gpu-memory-utilization` must be derived from the card that actually runs
the container.
