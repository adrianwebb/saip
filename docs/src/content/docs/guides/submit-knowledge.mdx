---
title: Submit Knowledge
description: Upload documents, code, and datasets through the Data API for training
---

Documents submitted through the inference gateway's Data API feed SAIP's training strategies. The inference gateway handles document processing because processors may need model inference (OCR, PDF parsing). Processed outputs are stored in R2, where the training gateway reads them during sleep mode. This guide covers supported formats, the submission endpoint, and how documents flow through the processing pipeline.

## Supported Formats

| Format | Extension | Max Size | Notes |
|--------|-----------|----------|-------|
| Plain text | `.txt` | 10 MB | UTF-8 encoded |
| Markdown | `.md`, `.mdx` | 10 MB | Frontmatter stripped during processing |
| Source code | `.py`, `.ts`, `.js`, `.rs`, `.go`, etc. | 5 MB | Language auto-detected from extension |
| JSONL | `.jsonl` | 50 MB | One JSON object per line |
| PDF | `.pdf` | 20 MB | Text extracted; scanned PDFs unsupported |

:::caution[Encoding]
All text files must be UTF-8 encoded. Files with BOM markers or non-UTF-8 encoding are rejected. Convert with `iconv -f LATIN1 -t UTF-8 input.txt > output.txt` if needed.
:::

### JSONL Format

JSONL files contain one document per line:

```jsonl
{"text": "The quick brown fox...", "source": "wikipedia", "license": "CC-BY-SA-4.0"}
{"text": "def fibonacci(n): ...", "source": "github/myrepo", "language": "python"}
{"text": "Meeting notes from 2024-03-15...", "source": "internal/notion", "tags": ["meetings", "q1"]}
```

Each line must be a valid JSON object with at least a `text` field. Additional fields are stored as metadata.

## Data API Endpoint

### Upload Documents

```
POST /v1/data/documents
Content-Type: application/json
```

The inference gateway listens on port **8000**. Documents are submitted through the inference gateway because document processors may need model inference (OCR, PDF parsing). The processed output is stored in R2 for the training gateway to consume.

#### Single Document

```bash
curl -X POST http://localhost:8000/v1/data/documents \
  -H "Content-Type: application/json" \
  -d '{
    "source": "internal/wiki/architecture.md",
    "source_type": "document",
    "content": "# Architecture\n\nSAIP uses a modular...",
    "license": "proprietary",
    "tags": ["architecture", "design"]
  }'
```

#### Dataset Submission

```bash
curl -X POST http://localhost:8000/v1/data/documents \
  -H "Content-Type: application/json" \
  -d '{
    "source": "external/arxiv/papers.jsonl",
    "source_type": "dataset",
    "content": "{\"text\": \"...\"}\n{\"text\": \"...\"}",
    "license": "CC-BY-4.0",
    "tags": ["ml", "research"]
  }'
```

#### Response

```json
{
  "id": "doc-20250115-001",
  "source": "internal/wiki/architecture.md",
  "source_type": "document",
  "hash": "sha256:a1b2c3...",
  "size_bytes": 4096,
  "processed_by": "markdown-processor",
  "created_at": "2025-01-15T10:30:00Z"
}
```

### List Documents

```
GET /v1/data/documents?limit=20&offset=0
```

Returns paginated results with metadata for each submission:

```bash
curl "http://localhost:8000/v1/data/documents?tag=onboarding&limit=10"
```

### Delete a Document

```bash
curl -X DELETE http://localhost:8000/v1/data/documents/doc-20250115-001
```

This removes the document and its processed outputs from R2. Already-completed training runs retain their data but won't include this document in future jobs.

## Request Fields

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `source` | string | Yes | Origin URI or description | `internal/wiki/onboarding.md` |
| `source_type` | string | Yes | Source classification: `document`, `repository`, or `dataset` | `document` |
| `content` | string | Yes | Raw document content (inline) | `# Onboarding Guide\n...` |
| `license` | string | No | SPDX license identifier | `MIT`, `CC-BY-4.0` |
| `tags` | string[] | No | Classification tags (array) | `["ml", "tutorial"]` |

:::tip[Source Conventions]
Use consistent source identifiers to enable filtering and deduplication downstream. Recommended patterns:
- GitHub: `github/<owner>/<repo>`
- Internal docs: `internal/<system>/<path>`
- External datasets: `external/<provider>/<dataset-name>`
:::

## Document Processing Pipeline

When you upload a document, it flows through a pluggable processing pipeline:

```
Upload → Validation → Dedup → Document Type Router → Document Processor Plugin → Processed Output
                                                                              ↓
                                                              Training Strategy Plugins
                                                              (convert to strategy-specific format)
```

### Step-by-Step

1. **Validation** — File format, encoding, and size are checked. Invalid files are rejected immediately with a descriptive error.

2. **Deduplication by hash** — Each document is SHA-256 hashed. If an identical hash already exists, the submission is marked as `duplicate` and skipped.

3. **Document Type Router** — Inspects the document's `source_type` and file extension to select the appropriate document processor plugin.

4. **Document Processor Plugin** — Runs within the inference gateway because processors may need model inference (OCR for scanned PDFs, structured parsing). Converts the raw document into an intermediate format. For example, a Markdown processor strips frontmatter and normalizes headings; a code processor preserves file structure and language metadata. Processors transform format — they do not split or chunk data.

5. **Training Strategy Plugins** — Each registered training strategy receives the processed output and converts it into its own required Axolotl dataset format:
   - **Knowledge Embedding** → completion-format text sequences
   - **Corrective SFT** → feedback-weighted message pairs
   - **Weighted KTO** → scalar reward records

6. **R2 Storage** — The original document and processed outputs are stored in the shared R2 bucket under `knowledge/`.

:::note[No Vector Database]
SAIP does not use vector databases, embeddings, or chunking for knowledge ingestion. Documents are transformed from one format to another by processor and strategy plugins. The training strategies consume the full processed output directly.
:::

## Resubmitting Updated Content

If a document has been revised:

1. Delete the old submission via `DELETE /v1/data/documents/:id`.
2. Upload the new version with the same `source` identifier.
3. The new hash ensures it passes deduplication.

:::caution[License Compliance]
You are responsible for ensuring submitted knowledge complies with its stated license. SAIP does not validate license compatibility. Submissions marked `proprietary` are included in training without restriction — only submit proprietary content you own or have explicit permission to train on.
:::

## Best Practices

- **Batch related documents** in JSONL format rather than uploading hundreds of individual files.
- **Tag consistently** — use a controlled vocabulary for tags to make filtering effective.
- **Set licenses accurately** — incorrect license metadata creates legal risk.
- **Review before training** — use `GET /v1/data/documents` to audit recent submissions before triggering a learning job.
- **Check available strategies** — use `GET /v1/learning/strategies` to see which training strategies can consume your document type.
