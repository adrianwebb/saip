SAIP requires several credentials for R2 storage, API authentication, and cloud provider access. This guide covers secure secret management across local and Hyperstack deployments.

## `.env` File Structure

SAIP reads environment variables from a `.env` file in the project root:

```ini
# === R2 Storage (required) ===
R2_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=abc123def456
R2_SECRET_ACCESS_KEY=xyz789ghi012jkl345mno678pqr901stu234
R2_BUCKET_NAME=saip-production

# === Inference Settings ===
SAIP_MODEL=Qwen/Qwen2.5-7B-Instruct-AWQ
SAIP_GPU_DEVICE=0
SAIP_MAX_MODEL_LEN=4096
SAIP_GPU_MEMORY_UTILIZATION=0.90

# === API Authentication ===
SAIP_API_TOKEN=sk-saip-xxxxxxxxxxxxxxxxxxxx

# === Hyperstack (optional, remote deployments only) ===
SAIP_HYPERSTACK_API_KEY=hsk_live_xxxxxxxxxxxx

# === Node Configuration ===
SAIP_NODE_ROLE=inference
```

### Required vs Optional Variables

| Variable | Required | Context |
|----------|----------|---------|
| `R2_ENDPOINT` | ✅ Always | R2 API endpoint URL |
| `R2_ACCESS_KEY_ID` | ✅ Always | R2 access key |
| `R2_SECRET_ACCESS_KEY` | ✅ Always | R2 secret key |
| `R2_BUCKET_NAME` | ✅ Always | Target R2 bucket |
| `SAIP_MODEL` | ✅ Inference | Model identifier |
| `SAIP_API_TOKEN` | ✅ Inference | API bearer token |
| `SAIP_HYPERSTACK_API_KEY` | ❌ Optional | Only for Hyperstack deployments |
| `SAIP_NODE_ROLE` | ❌ Optional | Defaults to `inference` |
| `SAIP_GPU_DEVICE` | ❌ Optional | Defaults to `0` |
| `SAIP_MAX_MODEL_LEN` | ❌ Optional | Defaults to `4096` |

:::caution[Never Commit `.env`]
The `.env` file contains secrets and must never be committed to version control. Verify it's in your `.gitignore`:

```bash
grep -q "^\.env$" .gitignore || echo ".env" >> .gitignore
```

Also ignore `.env.*` variants (`.env.local`, `.env.production`, etc.).
:::

## Docker Compose Integration

SAIP's Docker Compose configuration loads `.env` automatically via `env_file`:

```yaml
services:
  inference:
    image: saip-inference:latest
    env_file:
      - .env
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]

  worker:
    image: saip-worker:latest
    env_file:
      - .env
```

:::note[Compose Override]
Environment variables set directly in the `environment:` block override values from `env_file`. Use this for per-service overrides:

```yaml
services:
  inference:
    env_file: .env
    environment:
      - SAIP_NODE_ROLE=inference  # Overrides .env value
```
:::

### Multiple Environment Files

For multi-environment setups, layer environment files:

```yaml
services:
  inference:
    env_file:
      - .env                    # Base secrets (gitignored)
      - .env.local              # Local overrides (gitignored)
```

Files listed later take precedence. Keep shared non-secret config in a committed `.env.defaults` and secrets in the gitignored `.env`.

## Variable Interpolation in `saip.yaml`

SAIP supports `${VAR}` syntax in `saip.yaml` to inject environment variables at runtime:

```yaml
storage:
  endpoint: ${R2_ENDPOINT}
  bucket: ${R2_BUCKET_NAME}

inference:
  model: ${SAIP_MODEL}
  max_model_len: ${SAIP_MAX_MODEL_LEN:-4096}  # Default if unset

hyperstack:
  api_key: ${SAIP_HYPERSTACK_API_KEY}
```

### Interpolation Syntax

| Syntax | Behavior |
|--------|----------|
| `${VAR}` | Replaced with the value of `VAR`; error if unset |
| `${VAR:-default}` | Replaced with `VAR` if set, otherwise `default` |
| `${VAR:?message}` | Replaced with `VAR` if set; prints `message` and exits if unset |

:::tip[Sensible Defaults]
Use `${VAR:-default}` for optional settings to avoid requiring every variable in `.env`:

```yaml
inference:
  gpu_device: ${SAIP_GPU_DEVICE:-0}
  gpu_memory_utilization: ${SAIP_GPU_MEMORY_UTILIZATION:-0.90}
  max_model_len: ${SAIP_MAX_MODEL_LEN:-4096}
```
:::

:::caution[No Nested Interpolation]
Variable references are resolved in a single pass. `${VAR_${OTHER}}` is not supported and will be treated as a literal string.
:::

## Rotating Credentials

### R2 Keys

1. Generate new keys in the Cloudflare R2 dashboard.
2. Update `.env` with the new keys.
3. Restart services: `saip sleep && saip awake`.
4. Delete the old keys in the R2 dashboard.

:::note[Zero-Downtime Rotation]
R2 supports multiple active access keys simultaneously. Add the new key first, verify SAIP works, then revoke the old key. This avoids downtime during rotation.
:::

### API Tokens

1. Generate a new token: `saip token generate --name rotated-2024-03`.
2. Update `.env` and any client configurations.
3. Restart services.
4. Revoke the old token: `saip token revoke <old-token-id>`.

### Hyperstack API Keys

1. Generate a new key in the Hyperstack dashboard.
2. Update `.env` on all nodes.
3. Restart affected services.
4. Revoke the old key.

## Hyperstack Environment Injection

For remote deployments, inject secrets at instance creation time rather than copying `.env` files:

### Via Hyperstack Dashboard

1. Go to **Instances → Create Instance**.
2. Under **Advanced → User Data**, add environment exports:

```bash
#!/bin/bash
export R2_ENDPOINT="https://..."
export R2_ACCESS_KEY_ID="..."
export R2_SECRET_ACCESS_KEY="..."
```

:::caution[User Data Visibility]
Hyperstack user data is visible to anyone with dashboard access to the instance. For sensitive credentials, prefer the API injection method below or use a secrets manager.
:::

### Via Hyperstack API

Inject environment variables programmatically when creating instances:

```bash
hyperstack vm create \
  --name saip-inference \
  --image ubuntu-22.04-cuda-12.4 \
  --gpu rtx-a4000 \
  --env R2_ENDPOINT="$R2_ENDPOINT" \
  --env R2_ACCESS_KEY_ID="$R2_ACCESS_KEY_ID" \
  --env R2_SECRET_ACCESS_KEY="$R2_SECRET_ACCESS_KEY" \
  --env R2_BUCKET_NAME="$R2_BUCKET_NAME" \
  --env SAIP_API_TOKEN="$SAIP_API_TOKEN"
```

Variables injected this way are available in the instance's environment without writing a `.env` file to disk.

### Via Secrets Manager (Recommended for Production)

For production deployments, store secrets in a dedicated manager and fetch at boot:

```bash
# Example: fetch from HashiCorp Vault at instance startup
#!/bin/bash
vault kv get -format=json secret/saip/production | \
  jq -r 'to_entries[] | "export \(.key)=\(.value)"' > /etc/saip/env
source /etc/saip/env
rm /etc/saip/env
```

## Security Checklist

- [ ] `.env` is in `.gitignore`
- [ ] No secrets in committed files (check with `gitleaks` or `trufflehog`)
- [ ] R2 keys scoped to minimum required permissions
- [ ] API tokens rotated quarterly
- [ ] Hyperstack API keys restricted to necessary operations
- [ ] SSH keys use ed25519 or RSA-4096
- [ ] No secrets in Docker image layers (use runtime injection)
- [ ] Production secrets differ from development secrets
